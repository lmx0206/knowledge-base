# Codex 节省 Token 策略

> 来源：OpenAI 官方文档、社区实践
> 更新时间：2026年5月

## Codex 定价模型

```
┌─────────────────────────────────────────────────┐
│  Codex 定价                                      │
│                                                  │
│  ChatGPT 计划（推荐）：                           │

│    Pro：$200/月 — 更多使用量                     │
│    Business/Enterprise：团队计划                  │
│    Edu：教育计划                                  │
```

> 来源：OpenAI 官方定价页面


══════════════════════════════════════════════
  策略 1：使用 ChatGPT 计划
══════════════════════════════════════════════

```
最划算的方式：
  - Plus $20/月：日常开发足够
  - Pro $200/月：重度使用
  - 无需担心 token 计费

设置方法：
  codex 启动后选择 "Sign in with ChatGPT"
```


══════════════════════════════════════════════
  策略 2：精简 AGENTS.md
══════════════════════════════════════════════

```
AGENTS.md 的每一行都会消耗 token。

600 行 AGENTS.md ≈ 10-20K token（每次会话）

优化方法：
1. 保持 50-200 行
2. 只写 Codex 猜不到的信息
3. 详细内容放 docs/ 子目录
4. 定期删除过时规则

实测数据：
  600 行 AGENTS.md → 成功率 45%
  拆分后 200 行   → 成功率 72%
```

> 来源：DEV.to, "Harness Engineering Quick Actionable Guide"


══════════════════════════════════════════════
  策略 3：使用 codex exec
══════════════════════════════════════════════

```bash
# 非交互模式，无 TUI 开销
codex exec "fix the bug in auth.py"

# 临时会话（不保存 rollout 文件）
codex exec --ephemeral "quick task"
```

```
优势：
  - 无 TUI 渲染开销
  - 更直接的执行路径
  - --ephemeral 不保存历史（节省磁盘和后续加载）
  - 适合脚本化和 CI/CD
```


══════════════════════════════════════════════
  策略 4：精确指定文件
══════════════════════════════════════════════

```
不好的做法：
  "帮我优化这个项目"
  → Codex 可能读取大量无关文件

好的做法：
  "帮我优化 src/features/auth/login_viewmodel.dart"
  → Codex 只读取相关文件
```


══════════════════════════════════════════════
  策略 5：使用 Skills 而非重复说明
══════════════════════════════════════════════

```
不好的做法：
  每次对话都重复解释项目架构

好的做法：
  把架构信息写成 Skill，按需加载

Skills 的优势：
  - 只在需要时加载（节省 token）
  - 可复用（不用重复写）
  - 可维护（一处修改，处处生效）
```


══════════════════════════════════════════════
  策略 6：利用沙箱减少探索
══════════════════════════════════════════════

```
使用 workspace-write 沙箱：
  - Agent 只在工作目录内操作
  - 减少无意义的目录探索
  - 更快收敛到正确答案

使用 read-only 沙箱做代码审查：
  - Agent 只读不写
  - 专注分析，不浪费 token 在写操作确认上
```


══════════════════════════════════════════════
  策略 7：避免常见浪费
══════════════════════════════════════════════

```
浪费 1：让 Codex 读取整个项目
  → 明确指定需要读取的文件

浪费 2：重复解释需求
  → 写在 AGENTS.md 或 Skill 中

浪费 3：AGENTS.md 太长
  → 保持 50-200 行

浪费 4：不用 --ephemeral
  → 一次性任务用 --ephemeral

浪费 5：用 TUI 做简单任务
  → 简单任务用 codex exec
```
