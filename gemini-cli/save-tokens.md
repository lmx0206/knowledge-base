══════════════════════════════════════════════
  策略 1：使用 Google 账号登录
══════════════════════════════════════════════

```
最简单的方式：
  - 启动 gemini 后选择 "Sign in with Google"
  - 1000 次/天免费额度
  - 日常开发完全够用
  - 无需管理 API Key

如果需要更多：
  - API Key 也可以免费 1000 次/天
  - 付费用户有更高额度
```


══════════════════════════════════════════════
  策略 2：Token Caching（自动优化）
══════════════════════════════════════════════

```
Gemini CLI 自动优化 API 成本：
  - 系统指令和上下文自动缓存
  - 后续请求复用缓存内容
  - 减少重复处理的 token 数

支持：
  ✅ API Key 用户
  ✅ Vertex AI 用户
  ❌ OAuth 用户（Google 账号登录）暂不支持

查看缓存效果：
  /stats
```


══════════════════════════════════════════════
  策略 3：精简 GEMINI.md
══════════════════════════════════════════════

```
GEMINI.md 的每一行都会消耗 token。

优化方法：
1. 保持 50-200 行
2. 只写 Gemini 猜不到的信息
3. 使用 @file.md 导入拆分大文件
4. 定期删除过时规则
5. 使用 .geminiignore 排除无关文件
```

### GEMINI.md 导入语法

```markdown
# 主文件

## 项目概述
[基本信息]

@./docs/architecture.md

@./docs/coding-style.md
```

### .geminiignore

```
# 排除无关文件，减少上下文
node_modules/
build/
*.log
*.class
.gradle/
```

> 来源：Gemini CLI 官方文档 — GEMINI.md


══════════════════════════════════════════════
  策略 4：使用 Skills 渐进式加载
══════════════════════════════════════════════

```
Skills 的渐进式加载天然节省 token：
  - 会话开始时只注入名称和描述（几十 token）
  - 详细内容只在激活时注入
  - 不需要的 Skill 完全不占上下文

对比：
  把所有信息写在 GEMINI.md → 每次都消耗
  写成 Skills → 按需加载
```


══════════════════════════════════════════════
  策略 5：使用 Headless 模式
══════════════════════════════════════════════

```bash
# 非交互模式，无 TUI 开销
gemini --headless "fix the bug in auth.py"

# 脚本化批量处理
for file in src/*.py; do
  gemini --headless "Review $file for security issues"
done
```

```
优势：
  - 无 TUI 渲染开销
  - 更直接的执行路径
  - 适合脚本化和 CI/CD
```


══════════════════════════════════════════════
  策略 6：精确指定文件
══════════════════════════════════════════════

```
不好的做法：
  "帮我优化这个项目"
  → Gemini 可能读取大量无关文件

好的做法：
  "帮我优化 src/features/auth/login_viewmodel.dart"
  → Gemini 只读取相关文件

技巧：
  - 使用 @file 引用特定文件
  - 明确指定目录范围
  - 用 .geminiignore 排除无关目录
```


══════════════════════════════════════════════
  策略 7：利用 1M 上下文窗口
══════════════════════════════════════════════

```
Gemini 3 有 100 万 token 上下文窗口，
这意味着：
  - 不需要频繁压缩上下文
  - 可以一次加载整个项目的 AGENTS.md
  - 长对话也不容易"忘记"之前的内容

但也要注意：
  - 上下文越大，API 成本越高（即使是免费额度）
  - 还是应该精简 GEMINI.md
  - 1M 窗口是上限，不是目标
```

══════════════════════════════════════════════
  避免常见浪费
══════════════════════════════════════════════

```
浪费 1：GEMINI.md 太长
  → 保持 50-200 行，用 @file 导入

浪费 2：不使用 .geminiignore
  → 排除 node_modules、build、.gradle 等

浪费 3：让 Gemini 读取整个项目
  → 明确指定需要读取的文件

浪费 4：不用 Skills
  → 把重复信息写成 Skills

浪费 5：不用 Headless 模式
  → 简单任务用 --headless
```
